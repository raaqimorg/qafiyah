# Prosody Package Agent Guide

`qafiyah-prosody` is the Arabic prosody engine (علم العروض), in Python. Given a bayt, it reports which بحر the bayt fits and analyses its قافية. It is pure logic with no I/O, and nothing calls it yet. A future backend endpoint and UI will build on it. `docs/domain.md` defines the terms.

It was ported from a Dart engine written for a Flutter app, which is not in this repo. `python/tests/fixtures/dart-golden-100-bayt.json` is that engine's output on the first bayt of each of the 100 poems in `data/db/0000_default` (`sample-100-bayt.json`), and `tests/test_dart_parity.py` checks that this package reproduces it exactly.

`js/` is a line-for-line JavaScript port of the same Dart engine, with its own copy of the fixtures and an accuracy evaluation against the catalog labels (`js/TEST_REPORT.md`, regenerated by `node scripts/evaluate.js`). It does not pass the repo's lint gate (untyped code and `../` imports).

## Layout (`python/prosody/`)

- `poem.py`: the entry point. `analyze_poem(hemistichs)` returns `Ok` with one `BaytAnalysis` per bayt, or `Err(ProsodyError)`. Hemistichs are paired صدر/عجز. An odd count repeats the last hemistich, a lone hemistich is measured against itself, and an empty second hemistich is replaced by the first.
- `scan.py`: `scan_hemistich` first applies the ordered rewrite table (`REWRITES`). Order matters, because later rows assume earlier ones already ran. It then produces the arowdi writing and the `1`/`0` bits in one left-to-right pass over a window from two letters back to four ahead, with five spaces of padding on each side. If the line ends on a moving letter, it appends a `0` and stretches the final vowel (إشباع). It also holds the letter constants that `qafiyah.py` uses.
- `meter.py`: the تفعيلات with their bit patterns, the 22 بحور in search order (`BAHRS`, which is also the order of `meters` in the result), and `match_meters`. Each slot tries its allowed variants in order and the last fitting one wins; the next slot starts where it ended. A بحر matches when every slot of both hemistichs fits and the صدر bits are no longer than `max_length`. Trailing bits after the last foot are not checked.
- `qafiyah.py`: `analyze_qafiyah` reads the shape of the قافية from the tail of the عجز bits, then names الروي, الوصل, الخروج, الردف, التأسيس, الدخيل and their vowels from the arowdi writing (two characters per letter). An عجز too short for those reads is `Err(HEMISTICH_TOO_SHORT_FOR_QAFIYAH)`.
- `result.py`: `Ok`, `Err`, and `ProsodyError`, shared by the three modules above.

## Quirks kept from the Dart engine

- The متكاوس shape (`1011110`) is never recognised, because the shape search order repeats `101110`.
- An absent وصل is reported as `لايوجد` (no space), unlike every other absent part (`لا يوجد`).
- Stretching a final letter that carries no short vowel appends `-1` to the arowdi writing.

Behaviour changes to these, or to any rule, will fail `tests/test_dart_parity.py` on purpose. Re-record the golden fixture when that happens.

## Not ported from Dart

- The Flutter composer screen's live-typing state (`Taffelah.whereError`, `setError`, `findForWrite`, `setFindShatr`, and the `write` flag), because nothing in the analysis reads it.
- The table check that each slot only allows variants its base foot licenses, because the parity test already pins the table.
- The placeholder `لا نتيجة` result: no match is an empty `meters` tuple.

## Commands (from `python/`, needs `uv`)

```sh
uv run --group dev pytest
uv run --group dev ruff check . && uv run --group dev ruff format --check .
uv run --group dev mypy
```

Nothing in the repo gate runs these yet. The caches they leave (`.venv`, `.mypy_cache`, `.ruff_cache`, `__pycache__`) are ignored by git but not by `bun run check:naming`, so delete them before running the gate locally.
