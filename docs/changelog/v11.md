# Version 11

Released 2026-10-13, deploying the merge of release pull request #316 into `main`. The changes below are what this release adds to the previous deploy (4fc195f, version 10 and two hotfixes).

## Hotfixes

Both went straight to `main` and were deployed before this release.

- 2026-10-13, 109bfb6: below `md`, the space under the footer went from 80px to 56px.
- 2026-10-13, 4fc195f: the footer has its plain `py-4` again in every browser. Only X's in-app browser on iPhone (its user agent contains `Twitter for iPhone`) gets 56px under it, so X's toolbar no longer covers the footer links. A script in `<head>` marks that browser before the first paint.

## Changes

- Web: each page sends one `/api/me` request, shared by both account controls, instead of two. A signed-out visitor still sends it, so a failed accounts lookup cannot hide the account control for weeks (#319, closes #312).
- Infra: `api`, `web`, and `search-indexer` build on the host network, so `apk add` no longer fails at random on the IPv6 DNS servers that the default build network lists first (#318, closes #261).
- CI: the Docker jobs keep image layers in the GitHub Actions cache, so a run rebuilds only the images whose files changed. A warm run went from 11.5 to about 5.5 minutes. After a release, `bun run deploy` accepts the release pull request's passed CI run, when its commit has the same files as `main` (#317).
- CI: the Docker jobs install the server's Docker Compose 5.2.0 and Buildx 0.35.0, so CI builds the images the way the server does (#315, #318).
- Tooling: the script tests allow 30 seconds each, because an endpoint security agent can hold a new process for up to 12 seconds. `killGroup` also ignores `EPERM`, which macOS returns for a group whose processes have all exited, so the gate shows the failed task instead of crashing (#315, closes #296).

A plain deploy. It is the first deploy that builds on the host network.
