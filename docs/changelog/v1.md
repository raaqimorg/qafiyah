# Version 1

Released 2026-10-07, deploying ff53b1b. Version 1 is the baseline: it holds the whole project up to that commit, and the history before it lives in `git log`. The changes below are what this release added to the previous deploy (78f2f7d, 2026-09-28).

## Changes

- Verses: the API returns one `verses` entry per stored row and `verseCount` equals the number of entries, the random excerpt is one stored verse, search snippets are one row, and the website shows a single line on its own and free verse line by line (#204, closes #186). Dump 0039 repairs 2,803 classical poems whose verses were stored without their half-line split or as loose half-lines (#203).
- Poet page: filter a poet's poems by meter, rhyme, and theme, with a count on each option (#41).
- Architecture: the corpus and accounts databases and the search indexer read through Diesel, and the API and the indexer sit behind repository traits with a plain domain, with byte-identical responses (#146 to #149, #152 to #164).
- API: typed query parameters that refuse unknown ones and name the failing one (#192), every parameter and field documented with real examples and run in CI through Schemathesis (#187, #190), 503 with Retry-After and a 6 s deadline when a dependency is down (#171), rate-limit headers on errors (#184), Postgres timeouts for idle and abandoned work (#169), poem list totals read from the stats tables (#131, #134, #136, #143), and full Elasticsearch error causes in the logs (#202).
- Search: the oldest classical poem first for a quoted line, every reading of a poem searched, verse form filters with `/v1/poem-types`, hamza and letter folding, stopword-only queries, and faster highlighting from stored offsets with one merged segment per index (#27, #49 to #58, #69 to #78, #91 to #116, #126).
- Website: the page cache keyed on what each page reads, at most 10 requests in flight per visitor on the API and the website's proxy, and fixes to Arabic counts, the search history, the filter select, and the random poem's error page (#21, #28, #37, #38, #40, #46, #107, #130, #132, #172, #182).
- Observability: a private Prometheus, Loki, Alloy, and Grafana stack, reached with `bun run observe` (#193, #200, #201).
- Security: the fixes for GHSA-6333 (rate limits by IPv6 prefix) and GHSA-x5x6 (the poems pool).
- Dependencies: every npm package, Rust 1.99.0, Bun 1.4.2, Alpine 3.24, ModSecurity CRS 4.29, and Elasticsearch 9.5.4 (#43, #176 to #180).
- Docs and tooling: C4 architecture diagrams from one Structurizr model (#196), `api:compare` (#145), live progress and safer stops in `bun run dev` and `bun run ci` (#68, #72, #73, #80, #81, #83, #85), and the one-concern-per-module rule (#167).

## Release steps

1. Took an accounts database backup.
2. `bun run db:reseed -y`: restored dump 0039, started the new API (which applied the accounts migrations 0001 and 0002), moved Elasticsearch to 9.5.4, and rebuilt the search index.
3. `bun run deploy`: the website, the observability stack, and the edge gateway.

The restore ran an old copy of `scripts/db/init.sh`, so `random_poem_json` kept the dump's earlier version and the random poem answered 500 from 23:58 to 00:05 UTC, until `random-poem.sql` was run by hand.
