# Version 2

Released 2026-10-07, deploying the merge of release pull request #215 into `main`. The changes below are what this release adds to the previous deploy (ff53b1b, version 1).

## Changes

- Data: Faisal Al-Mansour's vocalized edition of seven Mu'allaqat is the primary reading at their existing URLs, and each older primary text moved to a new recension. Readings have an optional `source`, and poems record whether they carry tashkeel. The random poem draws only from vocalized poems with a two-half excerpt. Dump 0040 (#229, closes #118, #124, #125, #207).
- Observability: Grafana sends alerts to the Telegram group "Qafiyah Alerts" for downtime, the monitoring pipeline, the 5xx share, container memory, disk, and latency burn (#230, closes #194).
- Website: browser errors go straight to Sentry, and the telemetry-proxy Worker and the preconnect to `t.qafiyah.com` are gone (#231, closes #119).
- Search: a stack smoke probe guards the website's nginx search cache, the Edge dashboard charts its hit ratio, and the docs say how long cached searches live. No new cache layer (#232, closes #122).
- Search: a poet's damped poem count ranks famous poets above minor namesakes in poet search (#223, closes #185).
- Database: Postgres plans no parallel queries on its one CPU (#221, closes #205), and `db:reseed` recreates the database container before it restores, so the restore runs the checkout's `init.sh` (#220, closes #209).
- Smoke and gate: search is warmed before the smoke run probes a server it manages (#222, closes #208), the bad-bot probes use a URL that Cloudflare cannot answer from its cache (#218, closes #210), and the database test harness runs its own checks under a 60 second statement timeout (#234, closes #233).
- Dependencies: `sharp` is held at 0.35.5 or later (#219, closes #206).
- Docs: the Writing rules (about 80% of ASD-STE100), and every doc rewritten to them, with stale facts corrected (#224 to #228, closes #140).
- Process: version branches are found by `v` and a number only (#214, closes #213), and every open version keeps a draft release pull request (#217, closes #216).

## Release steps

1. Take an accounts database backup (`systemctl start qafiyah-accounts-backup.service` on the VPS).
2. `bun run db:reseed -y`: restore dump 0040, start the new API, and rebuild the search index.
3. `bun run deploy`: the website, the observability stack with the alerts, and the database container, which the deploy recreates because its command changed (#221).
4. Check the deploy with `bun run api:conformance prod`, and throw one test error in the browser to see that it reaches Sentry (#231).

This release needs no alert silence: the alerts arrive with the deploy, after the reseed.
