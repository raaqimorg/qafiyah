# Version 3

Released 2026-10-08, deploying the merge of release pull request #249 into `main`. The changes below are what this release adds to the previous deploy (a3a4a17, version 2).

## Changes

- Website: PostHog loads only in release builds, the same rule as Sentry, so local stacks and smoke runs no longer send page views (#237, closes #235).
- Website: PostHog comes from the `posthog-js` package, and PostHog's Sentry integration tags each browser error with the visitor's PostHog person (#242, closes #238).
- Website: PostHog events for searches (`search_completed`), the random poem button (`random_poem_requested`), and settings changes (`setting_changed`) (#243, closes #239).
- Website: cached pages no longer carry Sentry's trace tags, so each visitor starts their own trace, and the browser samples 10% of page loads (#251, closes #245).
- Website: the Sentry server config keeps only the options that differ from the defaults (#241, closes #236), and the build target names the browsers that the bundle needs (#250, closes #246).
- Observability: Grafana alerts the Telegram group when the daily accounts backup has not succeeded for 26 hours (#244, closes #240).

## Release steps

1. `bun run deploy`: the website, and the observability stack with the new Alloy mount and the backup alert.
2. Run one accounts backup by hand (`systemctl start qafiyah-accounts-backup.service` on the VPS). This creates the backup metric. Check that it shows in Grafana (#248).
3. When `search_completed` events arrive, add the event as a conversion goal in PostHog web analytics (#248).

This release needs no reseed, no reindex, and no alert silence.
